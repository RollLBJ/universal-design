# Web interfaces and responsive websites

Choose the archetype first: marketing, editorial, commerce, application workspace or data dashboard. Marketing pages may use a strong first-view proposition, product imagery and one useful call to action; application screens should immediately expose the task. Avoid generic hero copy, feature-card grids and filler testimonials. Use authentic content.

- Use semantic HTML and existing components; links navigate, buttons act, forms have persistent labels. Preserve URLs, history, deep links and shareable state where appropriate. Use proper focus order, visible focus, skip navigation for repeated chrome and predictable modal focus return.
- Build responsive layouts from content constraints, not one screenshot or arbitrary device model. Use flexible grids, sensible max widths for reading, wrapping and adaptive navigation. Verify narrow (e.g. 360 CSS px), medium and wide viewports; use project breakpoints when available. Test zoom and reflow; never disable zoom. Mobile touch interactions must not depend on hover.
- Marketing: align headline, actual visual evidence and action; alternate composition only where content calls for it. Editorial: readable measure, hierarchy, captions and navigation. Commerce: useful product details, accessible filters, transparent costs and honest checkout. Web apps: persistent task context, relevant data and accessible controls.
- Use the project's established framework, stylesheet/token system and assets. Avoid adding animation or UI libraries for superficial polish. Check loading, network errors, keyboard interaction and responsive overflow; verify actual rendered screenshots if possible.
- For web accessibility use WCAG (Web Content Accessibility Guidelines) as applicable, including contrast, keyboard access and target size requirements. Larger touch targets are useful even when the applicable minimum differs. Test reduced motion and zoom. Do not claim compliance from automated checks alone.
